hopviewer last 로그로 서버 점프(A→B→C→D)와 역순 SFTP 회수 시간표 정리

1. 서버 순서대로 last 로그 넣기 왼쪽이 출발 서버. last 출력(.txt, -F·-i·-a·--time-format iso 모두 가능) 또는 wtmp 파일(.gz 가능)을 각 칸에 끌어다 놓거나 붙여넣기

2. 접속 체인 · 타임테이블 왼쪽에서 체인을 고르면(↑ ↓ 키로 이동) 오른쪽에 그래프와 시간 순서표 — 계정명은 보지 않고 시간만 봅니다

첫 서버 로그인 시각 순 (오래된 것부터)

4. 노드 로그 보기 · 비교 한 노드의 last 로그를 날짜별로 보기 + 왼쪽(앞 노드) 세션을 누르면 오른쪽(다음 노드)에서 그 세션 시간 안에 완전히 들어간 로그인만 진하게 — A 로 들어와 B 로 점프한 세션 찾기용, 체인 판정과 별개로 원본 세션 그대로

판정 방법
· A 에서 B 로 접속한 세션은 B 의 last 에 남고, 그 세션이 살아 있는 동안 B→C, C→D 접속이 일어납니다. 그래서 다음 서버 세션의 [로그인~로그아웃]이 앞 서버 세션 안에 들어가면 그 둘을 부모-자식으로 잇습니다. 후보가 여러 개면 가장 늦게 시작한(가장 촘촘한) 앞 서버 세션을 고릅니다.
· 한 부모 아래에서 먼저 들어간 세션이 끝난 뒤(exit 로 복귀한 뒤) 다시 생긴 세션은 "재접속 — 파일 가져오기(sftp) 추정"으로 표시합니다. D→C, C→B, B→A 순서로 재접속이 이어지면 역순 회수 패턴으로 판정합니다.
· last 기본 출력은 시각이 분 단위로 잘려 있고 지속시간도 분 단위라 로그인/로그아웃이 최대 1~2분 어긋날 수 있습니다. 허용 오차로 조절하고, 가능하면 last -F -i(초·연도 포함)나 wtmp 원본을 쓰세요.
· sftp/scp 는 pty 를 쓰지 않아 OS·sshd 설정에 따라 wtmp 에 아예 안 남거나, tty 가 pts/N 이 아닌 값(notty 등)으로 남습니다. 회수 세션이 안 보이면 auth.log/secure 의 subsystem request for sftp 를 같이 보세요.
· IP 입력: 다음 서버의 last 에는 그 서버가 본 앞 서버의 출발지 IP 만 남습니다. 예를 들어 A 가 NAT 주소(공인 IP)로 B 에 접속하면 B 의 last 에는 A 의 실제 IP 대신 SNAT 된 주소가 찍히고, B 에서 C 로 갈 때는 C 의 last 에 B 의 실제 IP 가 찍힐 수 있습니다. 그래서 각 칸에 이 서버 실제 IP, 그리고 B 칸부터 앞 서버가 접속한 이 서버 주소(NAT, 참고용) 와 이 서버 last 에 찍히는 앞 서버 IP(비교용) 를 따로 적습니다. 비교는 세 값 중 하나라도 맞으면 일치로 보고, 어느 값과 맞았는지(지정·실IP·NAT)를 배지로 보여줍니다. A 에서 B 로 접속한 주소(NAT)는 wtmp 어디에도 남지 않으므로 순서표에 참고로만 표시합니다.
· 서버마다 시계가 다르면 각 칸의 시간 보정(초)에 더할 값을 넣으세요(예: B 시계가 90초 빠르면 -90). 연도 없는 last 출력은 wtmp begins 줄 → 요일 순으로 연도를 추정하며, 연도 칸에 직접 적을 수도 있습니다.
· /var/log/lastlog 는 계정별 마지막 1회만 있어 이 분석에 쓸 수 없습니다. last -F -i -f /var/log/wtmp 출력이나 wtmp(·wtmp.1) 파일을 넣으세요.
