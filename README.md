# wtmp-hopchain

여러 서버의 `last` / `wtmp` 로그만으로 **다단계 SSH 점프(A → B → C → D)와 역순 SFTP 회수(C←D, B←C, A←B)** 를
시간 순서표로 재구성하는 단일 HTML 뷰어입니다.

설치·서버·인터넷 없이 `hopviewer.html` 을 브라우저로 열기만 하면 됩니다. 로그는 브라우저 밖으로 나가지 않습니다.

## 무엇을 찾나

```
A 로그인 → A→B → B→C → C→D 점프
D 에서 exit → C→D 재접속(sftp 로 파일 가져오기)
C 에서 exit → B→C 재접속(sftp)
B 에서 exit → A→B 재접속(sftp) → A 로그아웃
```

A 에서 B 로 들어간 세션은 B 의 wtmp 에 남고, 그 세션이 살아 있는 동안 B→C, C→D 접속이 일어납니다.
그래서 **다음 서버 세션의 [로그인 ~ 로그아웃] 이 앞 서버 세션 안에 들어가면** 둘을 부모-자식으로 잇습니다.
계정명은 보지 않고 시간만 봅니다.

- 같은 부모 세션 아래에서 **먼저 들어간 세션이 끝난 뒤(exit) 다시 생긴 세션** → "재접속 — 파일 가져오기(sftp) 추정"
- 재접속이 깊은 서버부터 D→C, C→B, B→A 순서로 이어지면 → **역순 회수 패턴**
- 시간상 들어갈 수 있는 앞 서버 세션이 여러 개면 가장 늦게 시작한(가장 촘촘한) 세션을 부모로 고르고 `후보 N` 으로 표시

## 사용법

1. `hopviewer.html` 을 브라우저(Chrome·Edge·Firefox)로 엽니다. 처음이면 **예시 데이터** 로 동작을 확인하세요.
2. 서버 칸 A·B·C·D 에 **접속 순서대로** 각 서버의 로그를 끌어다 놓거나 붙여넣습니다. (`+ 서버 추가` 로 최대 26개)
3. **접속 체인 · 타임테이블** 화면에서 왼쪽 체인을 고르면(↑↓ 키) 오른쪽에 간트 그래프, 패턴 체크, 시간 순서표가 나옵니다.
   순서표는 복사하거나 CSV 로 저장할 수 있습니다.
   - 그래프에서 같은 서버에 시간이 겹친 세션은 줄을 나눠 그립니다. 서버 이름 아래 `세션 N · 동시 M` 은
     그 서버에 동시에 열려 있던 세션 수로, 터미널 창을 여러 개 띄워 작업했는지 볼 수 있습니다.
   - 막대 안에 시작 시각과 tty(`09:05 pts/1`)가 표시되고, pty 가 아닌 세션(notty 등, sftp·scp 가능)은 빗금으로 표시합니다.
   - 그래프 아래 `⛶ 크게 보기` 로 그래프만 화면 전체에 띄우고(Esc 로 닫기, 막대를 누르면 순서표의 그 행으로), `촘촘히` 로 줄 높이를 줄여 한 화면에 더 많이 볼 수 있습니다.
4. **노드 로그 보기 · 비교** (디버그용): 체인 판정과 별개로 원본 세션을 그대로 봅니다.
   "A 로 들어와서 B 로 점프한 세션" 을 직접 찾을 때 씁니다.
   - 한 노드만 골라 last 로그를 날짜별로, 하루 중 위치(0~24시) 막대와 함께 볼 수 있습니다.
   - 왼쪽(앞 노드) 세션을 누르면 오른쪽(다음 노드)에서 **그 세션 시간 안에 완전히 들어간 로그인만 진하게**,
     나머지는 흐리게 표시합니다. 경계에 걸치기만 한 세션은 관련 없는 것으로 봅니다. 오른쪽을 누르면 반대로 그걸 품은 왼쪽 세션을 표시합니다.
   - 왼쪽 행의 `→ B` 칸: 그 세션 안에 들어간 B 로그인 수와, 그중 출발지가 A 주소인 수(`IP✓n`).
   - 오른쪽 행의 `IP✓` / `IP✕`: 출발지가 A 의 주소(실제·NAT·지정)와 같은지. `IP✕` 는 B 에 직접 로그인한 것일 가능성이 큽니다.
   - `관련 있는 것만`: 왼쪽은 B 로그인을 품은 세션만, 오른쪽은 A 세션 안에 들어가는 로그인만 남깁니다.
     위쪽 `출발지 IP 일치만` 까지 켜면 IP 가 다른 세션도 빠집니다.

## 넣을 수 있는 로그

| 형식 | 예 |
|---|---|
| `last` 기본 출력 | `root  pts/0  10.0.0.5  Sat Oct  3 09:05 - 11:20  (02:14)` |
| `last -F` (초·연도 포함, 권장) | `... Sat Oct  3 09:05:30 2026 - Sat Oct  3 11:20:05 2026  (02:14)` |
| 날짜 숫자 표기 | `2026-10-03 09:05 - 11:20 (02:14)`, `2026/10/03 ...`, `10/03 ...` |
| `last --time-format iso` | `2026-10-03T09:05:30+09:00 - ...` |
| `last -a` (출발지가 줄 끝) | `root  pts/0  Sat Oct  3 09:05 - 11:20  (02:14)  10.0.0.5` |
| wtmp 바이너리 | `/var/log/wtmp`, `wtmp.1`, `wtmp.1.gz` |

서버에서 뽑을 때 권장 명령:

```bash
last -F -i -f /var/log/wtmp > $(hostname)_last.txt
```

`/var/log/lastlog` 는 계정별 마지막 1회 로그인만 있어 쓸 수 없습니다. `btmp` 는 실패 기록이라 대상이 아닙니다.

### 윈도우 서버가 끼어 있을 때 (예: A 리눅스 → B 윈도우 → C 리눅스)

윈도우에는 wtmp 대신 보안 이벤트 로그(4624 로그온 / 4634·4647 로그오프)가 있습니다.
`win_logons_to_last.ps1` 이 둘을 로그온 ID 로 짝지어 **last 형식(시간대 포함 ISO 날짜)** 으로 바꿔 주므로,
결과 파일을 B 칸에 그대로 넣으면 리눅스 서버와 똑같이 분석됩니다. tty 자리에는 로그온 종류(`type10` = RDP)가 들어갑니다.

```powershell
# 그 윈도우 서버에서 (관리자 PowerShell)
powershell -ExecutionPolicy Bypass -File .\win_logons_to_last.ps1 -Out B_last.txt
# 수집해 온 Security.evtx 를 분석 PC 에서 읽을 때
powershell -ExecutionPolicy Bypass -File .\win_logons_to_last.ps1 -Path .\Security.evtx -Out B_last.txt
# SSH(OpenSSH 서버)·sftp 로 들어온 로그온도 포함하려면 종류 3, 8 추가 (네트워크 로그온이 많아 잡음이 늘어남)
powershell -ExecutionPolicy Bypass -File .\win_logons_to_last.ps1 -Path .\Security.evtx -LogonTypes 2,3,8,10,11
```

## 옵션

- **기간으로 끊어 보기**
  - 체인 목록: 위쪽에서 `월`·`주`·`일` 을 고르고 ◀ ▶ 로 넘기면 그 기간에 출발한 체인만 보입니다(1년치도 한 달씩).
    체인이 없는 기간은 건너뛰고, 필터 숫자도 그 기간 기준입니다.
  - 그래프·순서표: 상세 화면 `보기 기간` 에서 출발 세션 생명주기 안의 구간만 잘라 봅니다. 날짜 직접 입력, `하루`·`한 달`
    (◀ ▶ 가 달력대로 다음 날·다음 달), 그래프 드래그 = 확대, 더블클릭 = 전체. 체인 판정은 바뀌지 않고 보는 범위만 바뀝니다.
    `긴 세션 상한` 을 0 으로 두고 몇 달짜리 세션을 이 기능으로 나눠 보는 것도 방법입니다.
- **긴 세션 상한(시간, 기본 24)**: 로그아웃 기록이 없거나(`still logged in`·`gone`) 몇 달씩 이어진 세션은 그 기간 다음 서버의
  모든 로그인을 자식으로 빨아들여 세로줄이 빽빽한 빗 모양 체인을 만듭니다. 그래서 부모로 볼 때는 시작 후 이 시간까지만 인정하고,
  체인 목록에 `장기 4개월`·`로그아웃 없음` 경고를, 그래프에는 실제 끝(`→ 10-15 11:15`)을 표시합니다. 0 이면 제한 없음.
- **로컬 로그인 제외**: tty 가 `seat0`·`:0`·`:1`·`tty1` 이거나 출발지가 비어 있는(`:0`, `tmux(…)` 포함) 세션은
  그 서버 앞(GUI·콘솔)이나 tmux 안에서 생긴 것이라 앞 서버에서 점프해 온 자식으로 보지 않습니다. 서버 칸에 제외 개수가 나옵니다.
- **킵 (나중에 다시 보기)**: 체인 목록의 ☆ 또는 상세 화면 위 `☆ 킵` 을 누르면 그 순간의 체인·비교 라인·순서표와
  당시 설정(허용 오차, 출발 IP, 서버 구성)을 통째로 보관합니다. 왼쪽 위 `★ 킵` 탭에서 고르면 나중에 설정을 바꿨거나
  로그를 더 넣었어도 **그때 모습 그대로** 다시 보여 줍니다.
  - 메모를 달 수 있고, `지금 분석에서 찾기` 로 현재 분석 결과의 같은 체인(같은 출발 세션)으로 이동합니다.
  - 킵은 이 브라우저에 저장됩니다. 브라우저 데이터를 지우면 사라지니 `내보내기`(JSON)로 파일에 남기고, `가져오기` 로 다시 불러오세요(보고서 첨부·다른 PC 로 옮기기).
- **비교 서버 (경유지를 모르는 종착 서버)**: 서버 칸의 `ON` 버튼(또는 체인 목록 위 서버 버튼)을 누를 때마다
  `ON(체인)` → `비교` → `OFF` 로 바뀝니다. A-B-C 는 확실하고 D 는 종착지인데 C 와 D 사이 경유지를 모를 때 D 를 `비교` 로 두면,
  D 는 짝을 맞추지 않고 **고른 체인 시간대의 D 로그인을 그래프 아래 별도 줄과 순서표에 같이** 보여 줍니다.
  - 체인 마지막 서버(C) 세션 안에 완전히 들어간 D 로그인 = 진하게("체인 안"), 체인 시간대와 겹치기만 한 것 = 흐리게
  - 체인 목록에 `D 2` 같은 배지(체인 안 D 로그인 수), `비교 겹침` 필터로 D 로그인이 있는 체인만 추리기
  - 체인 마지막 서버 세션이 길면(계속 접속 중 등) 관계없는 D 로그인도 "체인 안" 으로 잡히니, 출발 IP 필터와 같이 쓰는 것을 권장
  - 비교 서버는 여러 개 둘 수 있습니다(서버마다 대조 라인 한 줄). `+ 비교 서버 추가` 로 처음부터 비교 상태인 칸을 만들 수 있고, 서버 칸은 최대 26개입니다.
- **출발 IP (공격자 IP)**: 출발 서버(A) 칸 또는 작업 화면 왼쪽 위 칸에 A 에 접속한 IP 를 넣으면,
  그 IP 에서 들어온 A 로그인만 남기고 거기서부터 B·C·D 로 이어 갑니다. 다른 사람의 A 로그인과
  그 아래에서 일어난 B 접속은 체인에 붙지 않고, 체인도 A 에서 시작하는 것만 나옵니다.
  여러 개(쉼표), 대역(`45.133.1.0/24`), 접두(`91.240.*`) 를 쓸 수 있습니다.
- **갈라지는 경로 (앞 서버)**: 서버 칸마다 `앞 서버` 를 고를 수 있습니다. 기본값 `자동` 은 바로 왼쪽 칸이라
  일직선(A→B→C→D)은 그대로 쓰면 되고, C 에서 C' 로도 갔다면 C' 칸을 추가해 `앞 서버 = C` 로 고르면
  `A→B→C→D, C→C'` 구조로 분석합니다. 회수(exit 후 재접속)와 역순 판정은 서버 연결(C→D, C→C' …)마다 따로 봅니다.
- **서버 켜기/끄기**: 서버 칸의 `ON/OFF` 또는 체인 목록 위 `서버 A B C D` 버튼으로 일부 서버만 분석합니다.
  D 를 끄면 A→B→C 만, B 를 끄면 A 세션 안의 C 접속을 **A→C 직접 접속**으로 비교합니다.
  건너뛴 구간은 C 의 last 에 A 가 직접 찍히므로 A 의 실제·NAT IP 와 비교합니다.
- **서버 순서 바꾸기**: 서버 칸 제목 옆 `◀` `▶` 로 순서를 옮깁니다. 앞 서버를 깜빡했으면 `+ 서버 추가` 후 맨 앞으로 옮기면 됩니다.
  각 칸의 "← 앞 서버에서 들어올 때" 값은 그 칸에 그대로 남으니, 순서를 바꾼 뒤 맞는지 확인하세요.
- **체인 목록 순서**: 첫 서버(출발 세션)의 로그인 시각 순, 오래된 것부터.
- **허용 오차(초)**: `last` 기본 출력은 분 단위라 기본 60초. 초 단위 로그면 줄여도 됩니다.
- **시간 보정(초)**: 서버마다 시계가 다르면 칸별로 더할 값을 넣습니다. (예: B 시계가 90초 빠르면 `-90`)
- **연도**: 연도 없는 출력은 `wtmp begins` 줄 → 요일 순으로 추정합니다. 틀리면 칸에 직접 적으세요.
- **서버 IP (NAT 고려)**: 다음 서버의 wtmp 에는 *그 서버가 본 앞 서버의 출발지 IP* 만 남습니다.
  NAT 가 끼면 이 값이 앞 서버의 실제 IP 와 다를 수 있어서, 주소를 역할별로 나눠 적습니다.

  | 칸 | 예 | 쓰임 |
  |---|---|---|
  | 이 서버 실제 IP | B: `10.10.2.20` | 다음 서버(C) 로그의 출발지와 비교 |
  | ← A 에서 들어올 때: A 가 접속한 이 서버 주소 | B: `203.0.113.20` (NAT) | wtmp 에 안 남음 — 순서표에 참고로 표시 |
  | ← A 에서 들어올 때: 이 서버 last 에 찍히는 A 의 IP | B: `198.51.100.7` (A 의 SNAT 주소) | B 로그의 출발지와 비교 |

  세 값 중 하나라도 맞으면 일치로 보고 어느 값과 맞았는지(`지정`·`실IP`·`NAT`)를 배지로 보여줍니다.
  `출발지 IP 일치만` 을 켜면 시간만 우연히 겹친 세션을 걸러냅니다.
  B 칸부터 "시간이 맞는 출발지" 가 제안되며, 누르면 "last 에 찍히는 IP" 칸에 들어갑니다.
- **표시 시간대**: wtmp 바이너리와 ISO(시간대 포함) 시각을 이 시간대로 바꿔 보여줍니다.

## 한계

- 공격자가 터미널 창을 여러 개 띄워(A, A→B, A→B→C, A→B→C→D) 창을 닫지 않은 채 sftp 로 끌어오면,
  점프 세션이 열린 채라 "exit 후 재접속" 규칙으로는 회수로 잡히지 않고 "기타 접속" 으로 나옵니다.
  또 창들을 1~2분 간격으로 열면 시간만으로는 어느 창의 세션인지 갈라지지 않을 수 있습니다.
  이때는 그래프의 `동시 N` 과 빗금(pty 아님) 막대, 4번 노드 비교 화면으로 사람이 해석해야 합니다.
- `last` 기본 출력은 시각이 분 단위로 잘려 있어 1~2분 어긋날 수 있습니다. 가능하면 `last -F` 나 wtmp 원본을 쓰세요.
- sftp/scp 는 pty 를 쓰지 않아 OS·sshd 설정에 따라 **wtmp 에 아예 안 남거나** tty 가 `pts/N` 이 아닌 값으로 남습니다.
  회수 세션이 안 보이면 `auth.log` / `secure` 의 `subsystem request for sftp` 를 같이 확인하세요.
- 시간 겹침만으로 판정하므로 같은 시간대에 다른 사람이 접속했다면 잘못 이어질 수 있습니다. 서버 IP 를 채우면 줄어듭니다.

## 성능

서버당 세션 50,000개 × 4대를 약 0.7초에 분석합니다. 시작 시각 정렬과 구간 최대값 트리로 짝을 찾아 세션당 O(log n) 입니다.
화면에는 체인 120개, 순서표 1,500행, 세션 표 1,000행까지만 그리고, 복사·CSV 에는 전부 들어갑니다.
